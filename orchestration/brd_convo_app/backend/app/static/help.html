Author's Guide & Cheat Sheet

Everything you need to prepare, set up, and author a Blueprint Document for a Kinaxis RapidResponse implementation using the Blueprint Document Agent.

BristleCone Accelerator Kinaxis RapidResponse Pre-read before your first Blueprint Document

What does this tool do?

The Blueprint Document Agent is an AI-assisted authoring tool that generates Blueprint Document sections from your uploaded source materials (workshop transcripts, RFPs, SOWs, existing blueprints) and process images (Kinaxis screenshots, swimlane diagrams). It does not fabricate content — it synthesises from what you upload.

Key principle: The quality of the output is directly proportional to the quality and completeness of what you upload. Garbage in, garbage out — complete transcripts in, polished Blueprint Document out.

1 Gather — Before You Open the Tool

Workshops & Transcripts

  • All functional design workshops completed — Demand Planning, Supply Planning, Inventory, Data Integration, Governance
  • Workshop transcripts exported as .docx or .txt — one file per workstream
  • Transcripts cleaned up (remove filler, add context where the recording was unclear)
  • Meeting notes / whiteboard photos consolidated into a single notes document
  • Action items and open questions list noted separately (these signal gaps the agent cannot fill)
Do not start authoring if workshops are incomplete. The agent will generate plausible-sounding but generic content for any area with no transcript — which is worse than a blank section because it looks complete but isn't.

Client Source Documents

  • RFP or RFI from the client
  • Signed SOW or contract (confirms scope boundary)
  • Current-state process maps (as-is)
  • Organisation chart or RACI (for governance section)
  • Data integration specification / IT architecture document
  • Any existing blueprint from a prior engagement phase
  • Client-provided master data specs (part data, site data)

Kinaxis Screenshots

Screenshots make user stories concrete and give the agent visual context to reference. Aim for one screenshot per named user story or process step.

  • Planning sheet screenshots — Demand, Supply, Inventory
  • Key RapidResponse screens referenced in scope:
    • Forecast Item configuration
    • Firm Planned Orders / Order Firming screen
    • Safety Stock / Min-Max settings
    • S&OP Demand Snapshot calendar
    • Batch jobs / scheduled task setup
    • Custom workbooks or taskflow screens
  • Screenshots of any configured automation chains
  • Export settings and integration log screens (for data integration section)
Format: Export as PNG or JPEG. Avoid EMF / WMF (vector metafiles) — they may not render. Minimum 100 KB per image for useful vision analysis.

Process Diagrams

  • Level 2 process flow diagrams — one per major process (Demand Planning, Supply Planning, Inventory, Data Integration)
  • Level 3 swimlane diagrams for detailed sub-processes
  • Data flow / integration architecture diagram
  • Kinaxis standard process library diagrams (if licensed)
  • Any RACI or governance diagrams
Export as PNG or JPEG from Visio or PowerPoint. PowerPoint diagrams — save each slide as an image, or export as PPTX and upload the whole file (images are extracted automatically).

User Story Sheet

  • User story spreadsheet (.xlsx) with columns: ID · Role · User Story · Acceptance Criteria · Priority · Blueprint Document Section
  • Stories grouped by workstream / Blueprint Document section
  • Reviewed and confirmed by the client (or at least the lead consultant)
  • All acceptance criteria written in measurable terms
Upload the user story XLSX to the repository. When generating any section that describes configured behaviour, pin the relevant user story chunk to that section before generating.

2 Setup — Configure the Tool

Step 1 — Create a Project

  1. Go to Projects → click New Project
  2. Enter client name, project name, set Status = Active
  3. Note the project ID — you'll reference it throughout

Step 2 — Upload Source Documents

  1. Go to Repositories → create a new Repository (e.g., "Arclin Source Docs")
  2. Upload files one by one — workshop transcripts first, then RFP, SOW, user stories, existing blueprint
  3. Wait for each file to show status = Indexed and a chunk count > 0
  4. If any file shows Indexed, 0 chunks — click ↻ Re-index next to it
  5. Link this repository to your project: go to Projects → select project → Repositories tab → Link
Accepted formats: .docx · .pdf · .xlsx · .pptx · .txt. Maximum file size: 50 MB.

Step 3 — Upload Images to the Image Library

  1. Go to Image Library → create a new image Repository (e.g., "Arclin Process Diagrams")
  2. Upload all Kinaxis screenshots and process diagrams
  3. Wait for vision analysis — each image receives a caption and keywords automatically (requires internet connection for GPT-4o)
  4. Open the Editor for your project → click Browse Images → click Auto-tag Kinaxis to tag all Level 2 / Level 3 diagrams
  5. Link this image Repository to your project: Projects → select project → Image Repositories tab → Link
Uploading a whole PowerPoint file to a document repository will also extract all embedded slide images automatically and add them to the image index.

Step 4 — Apply a Template

  1. Go to Templates → click Import → upload your standard Blueprint Document .docx template (headings drive the section structure)
  2. Open the template and configure each section:
    • Doc keywords — what the agent searches in uploaded documents
    • Web keywords — for online research (use sparingly)
    • Custom prompt — specific instructions for this section
    • Heading Only toggle — for TOC / executive summary sections (no generation needed)
  3. Click Apply to Project → select your project

3 Author — Section by Section

Section Workflow (repeat for every section)

  1. Open the section in the Blueprint Document Editor
  2. Browse Chunks — verify source content exists, pin the best 2–3 chunks
  3. Browse Images — find and pin the most relevant diagram + screenshot
  4. Generate — the agent drafts the section from your pinned content
  5. Review — fact-check against transcripts, fix names, edit inline
  6. Approve the section when satisfied
Pinning is the single biggest lever for quality. Pinning 2–3 specific chunks gives far better results than relying on keyword search alone — the agent reads exactly what you pinned instead of guessing.

Browse Chunks — Tips

  • Search using single concepts first — e.g., "demand forecast", "S&OP", "safety stock"
  • If no good chunks appear for a section, the source material may be missing — upload it before generating
  • Use Pin to Section for the 2–3 chunks most directly relevant to the section topic
  • Use Use as doc keywords to extract keywords from selected chunks and add them to the section config
  • For user story sections, always pin the relevant rows from the user story XLSX chunk
  • For data integration sections, pin the interface specification chunk explicitly

Browse Images — Tips

  • Search by concept keywords — "firm planned orders", "forecast item", "safety stock"
  • Search by source filename — e.g., "DEMAND 1" to see all images from that file
  • Use multiple words — the search finds images where ALL words appear anywhere in the caption, keywords, or description (e.g., "firm MPS orders")
  • Filter by Kinaxis Process Diagram tag to see only Level 2 / Level 3 process flows
  • Pin 1 process diagram + 1 screenshot per section for best results
  • Click an image to preview it before pinning
If an image is from a PPTX or uploaded Repository but doesn't appear, check that the file was re-indexed after the initial upload. The image library is searchable immediately after vision analysis completes.

Generate & Review Checklist

  • Pinned chunks include the primary source for this section's content
  • At least one process diagram is pinned for any process description section
  • Client name appears correctly (not "Client" or "Customer" placeholder)
  • Process steps match what was agreed in workshops — compare against transcript
  • Kinaxis screen references match the actual screenshots pinned
  • Any user story acceptance criteria are measurable, not vague
  • No Lorem Ipsum, "[TBD]", or "[INSERT]" text remains
  • Section length is appropriate — not padded with generic Kinaxis boilerplate
If a section generates generic boilerplate with no client-specific content, go back to Browse Chunks and pin more specific source material, then regenerate.

4 Review & Export

Quality Check

Click the amber Quality Check button in the editor toolbar before exporting. The check runs in two passes:

  1. Structural pass — flags empty sections, stub content (<80 chars), unresolved image tags, generic "Client Name" placeholders, unfilled [BRACKETS]
  2. LLM review pass — GPT-4o reads all section outputs and flags inconsistencies, contradictions, template language, and missing client-specific content
  • Fix all RED findings before exporting (empty / broken sections)
  • Review all AMBER findings — most need a human decision
  • A clean quality check ≠ a perfect document, but it catches the obvious issues

Export to Word

  1. All sections approved? Click Export in the editor toolbar
  2. A .docx file downloads with all text and embedded images
  3. Open in Word and apply your firm's document style / cover page template
  4. Do a final read-through — check page breaks, image sizing, table formatting
  5. Send for internal review before sharing with client

Search Tips — Browse Images & Browse Chunks

Both search boxes match all words independently — they don't need to appear as a phrase.

Examples that work:

firm MPS orders demand snapshot calendar safety stock replenishment Level 2 supply STO demand ARC DEMAND 1

Scope of image search — searches across: caption · keywords · description · section heading · source filename · tags

Scope of chunk search — searches across: heading · text content · source document name

If you can't find an image, try searching just one distinctive word from the caption (e.g., "firmed" or "snapshot"). The full phrase may not match but individual words will.
